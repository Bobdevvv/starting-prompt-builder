# Writing for people

**Prevents:** documentation and interface text that is padded, vague, or sounds
like an advert.

## Rules

- Plain words, short sentences, active voice.
- Say what something does and how to use it. Leave out how impressive it is.
- Use one term for one thing throughout, and define it the first time.
- Match the voice of the text that's already there. If there isn't any, ask me
  for an example.

## Why these rules

**Generated text tends towards filler and enthusiasm** unless asked otherwise.
That's a common observation, not a measured one. Four short rules give the
session a concrete standard instead of "write well".

**Matching the existing voice** keeps a project reading as one piece.

## Sources

- These rules are general writing practice, not from a single source.

## How it could be tested

**Needs a judge:** a reader compares the text with and without the module,
blind to which is which. Not scriptable in any meaningful way.
