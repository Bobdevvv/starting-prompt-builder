# Explain as you go

**Prevents:** ending a session with working code you can't explain, change or
debug.

## Rules

- When you make a choice that isn't obvious, explain it in a sentence or two
  and name the alternative you didn't take.
- Name new concepts, patterns and tools when they first come up, so I can look
  them up.
- Prefer small steps I can follow over large changes at once.
- Skip explanations of things I've shown I already know.

## Why these rules

**Explaining by default makes every reply longer,** so this is a module, not
part of the core. Naming the rejected alternative shows that a decision was
made, and what it was weighed against.

## Sources

- None. These rules are a teaching preference, not from a published source.

## How it could be tested

**Needs a judge:** do the replies name alternatives and concepts? This one
changes how replies read, not what the session does, so a script can't score
it.
